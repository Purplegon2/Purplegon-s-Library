powderJS — Scripting & Materials (quick reference)

Materials — adding / fields

Add a material object to the material arrays (grouped lists). Use human names for transforms (IDs are auto-assigned at load by buildMaterialsTable()).

{
  name: "MyMetal",
  short: "METL",            // 4 chars shown in UI
  state: "solid",           // "solid" | "liquid" | "gas" (physical behaviour)
  category: "solid",        // UI grouping (optional)
  color: "#aabbcc",         // base color (hex)
  colorVar: 0.06,           // per-cell jitter (0..1)
  density: 7.8,
  conductivity: 0.7,
  heatCapacity: 0.5,
  defaultTemp: 20,          // applied when painted (optional)
  immovable: true,          // prevents displacement
  nuclear: false,           // flag for nuclear rules (optional)
  burnable: true,
  ignitionTemp: 300
}

Important transform fields (use material name strings): meltInto, freezeInto, boilInto, condenseInto, decayInto.

Scripting API (per-material)

Materials may include a script string and scheduling fields. Scripts compile once and run with this bound to the cell object when executed.

{
  name: "Acid",
  state: "liquid",
  script: `
    // 'this' is the current cell object
    // canvas and game objects are provided as globals to the script
    const parts = canvas.find_particles(this.x, this.y, 1, null, 32);
    for (const p of parts) {
      if (p.x===this.x && p.y===this.y) continue;
      if (!p.matId) continue;
      if (p.matId === this.mat.id) continue;
      // skip hot materials
      if ((p.temp||20) > 100) continue;
      canvas.set(p.x, p.y, 'Air');   // immediate change scheduled
      this.temp = (this.temp||20) + 30;
    }
  `,
  scriptInterval: 6,   // ticks between executions (1 = every step)
  scriptParams: {}
}

Exposed objects / functions inside scripts

  • this: cell context — fields include x,y,matId,temp,pressure,mat (mat is material descriptor)
  • canvas.get(x,y) → {x,y,matId,temp,pressure} or null
  • canvas.set(x,y, "Air" | "MyMat" | id) — schedule cell replacement
  • canvas.replace_particle(pos, materialNameOrId) — helper to swap a particle
  • canvas.find_particles(cx,cy,r,filter,limit) — returns neighbor particle objects
  • canvas.forEachNeighbor(x,y,fn) — iterate 8 neighbors
  • game.getMat(name) — material descriptor
  • game.spawnEntity(type, x,y, params) — spawn an entity
  • game.triggerExplosion(x,y, opts ) — helper explosion
  • helpers.rand(), helpers.randint(a,b) — small helpers

Scripts run inside try/catch. Use scriptInterval to throttle; heavy scripts can kill frame-rate.

Script scheduling & safety

  • scriptInterval: integer ticks between runs (default: material-specific or higher value for expensive scripts).
  • sampleRate (optional): probability 0..1 to run when interval hits.
  • Scripts are sandboxed to the provided helpers and the cell this. Avoid infinite loops and expensive global scans.
  • All writes via canvas.set and helpers are batched and committed after the script pass.

Thermal / painting notes

  • When painted, a material's defaultTemp (if present) is applied to the spawned pixels.
  • Temperature and pressure are tracked per-cell and follow particle movement (moves transfer cell temp/pressure).
  • Use burnable + ignitionTemp to enable automatic fire conversion.

Nuclear & entity notes

  • Set entity: true and behavior to create moving entities (e.g., Neutron). Entities do not occupy a persistent grid tile unless explicitly placed.
  • Set nuclear: true plus fission properties (fissionOnNeutron, criticalTemp, fissionYield) to enable fission behavior.
  • Materials can be marked neutronAbsorber or neutronReflector to change neutron interactions.

Developer tips

  • Reload the page after editing materials.js (or use the UI Reset) so new materials/scripts compile.
  • Prefer short-range operations and batched writes in scripts. Use scriptInterval = 8..30 for expensive logic.
  • Use game.getMat("Air") to resolve names; transforms must refer to material names, not numeric ids.
