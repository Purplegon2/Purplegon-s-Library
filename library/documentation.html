Built-in Markup

Nova is JavaScript with stricter rules and built-in pages.

Nova compiles to JavaScript, but removes common JS foot-guns by default, simplifies control flow syntax, and provides a page + html { … } system that compiles to DOM-builder JavaScript.

Target: ES Modules
Web: index.html + app.js
Markup: html { … } → DOM
Typing: strict by default
Nova v0 goals
  • No required parentheses in if.
  • elif + and/or aliases.
  • if as an expression.
  • Strict equality and no implicit coercion.
  • Pages compile to DOM builder + small runtime.

Typing & coercion differences vs TypeScript and JavaScript

Nova aims for “TypeScript-level static safety” plus stricter runtime behavior by preventing implicit coercion. These guarantees come from the Nova compiler (like TypeScript); generated JS still runs on the JS runtime.

Type checking

  • No implicit any: if a value cannot be typed, it’s a compile error (or requires an explicit escape hatch).
  • Inference is allowed: but inferred types must stay consistent.
  • Nullability is explicit: use T? for nullable types (recommended for v0).

Coercion rules

  • Bool-only conditions: if conditions must be bool.
  • Strict equality: == behaves like ===; != like !==.
  • No string/number mixing: use .. or explicit conversions.
  • Explicit conversions: toInt, toNum, toStr (library-defined behavior).
// Nova (recommended)
let n = 1 + 2        // ok
let s = "a" .. "b"   // ok
let bad = "x" + 2    // error

// Nova: bool-only conditions
let name = ""
if name { ... }      // error
if name != "" { ... } // ok

Control flow

If as an expression

// Nova
let x =
  if a < b: 1
  elif a + b == c: 2
  else: 3

// Typical JS output (IIFE form)
const x = (() => {
  if (a < b) return 1;
  else if (a + b === c) return 2;
  else return 3;
})();
Why IIFE output? It avoids nested JS ternaries while keeping expression semantics.

Classes & object orientation

.new syntax sugar

// Nova
class Vec2 {
  let x: number
  let y: number

  new(x: number, y: number) {
    this.x = x
    this.y = y
  }

  add(v: Vec2) -> Vec2 {
    return Vec2.new(this.x + v.x, this.y + v.y)
  }
}

let p = Vec2.new(1, 2)

// Typical JS output
class Vec2 {
  constructor(x, y) { this.x = x; this.y = y; }
  add(v) { return new Vec2(this.x + v.x, this.y + v.y); }
}
const p = new Vec2(1, 2);

Optional compile-time convenience: implicit this. for known fields inside class methods.

Modules

  • Nova compiles to ES Modules by default (import/export).
  • Imports can reference .nova sources and resolve to generated .js outputs.
  • Compiler may optionally bundle to a single JS file for browsers.
// Nova
import { Vec2 } from "./vec2.nova"
export func main() { ... }

// JS output
import { Vec2 } from "./vec2.js";
export function main() { ... }

Built-in web pages (Option 1 + Option A)

Nova adds page definitions plus html { ... } template blocks. A page compiles to a function returning a DOM node (or fragment).

Rules

  • page Name(): declares a render function.
  • html { ... }: HTML-like markup only (no doctype, no <script> inside).
  • {expr} interpolation: inject Nova expressions into text/attributes.
  • Event binding: onclick={handler}, oninput={handler}, etc.
  • Scope: markup can reference symbols in surrounding Nova scope.

Example

// Nova
page home() {
  let title = "Nova"
  func clickMe() { print("clicked") }

  html {
    <div class="panel">
      <h1>{title}</h1>
      <button onclick={clickMe}>Click</button>
    </div>
  }
}

Mounting

// Nova
run home

// Desugars to
mount(home(), "#app")

Compilation model (DOM builder)

Templates compile into document.createElement calls, safe text assignment, attribute setting, and addEventListener for events. 

// Typical JS output (simplified)
export function home() {
  const root = document.createElement("div");
  root.className = "panel";

  const h1 = document.createElement("h1");
  h1.textContent = title;
  root.appendChild(h1);

  const btn = document.createElement("button");
  btn.textContent = "Click";
  btn.addEventListener("click", clickMe);
  root.appendChild(btn);

  return root;
}

State (minimal v0 runtime)

v0 can ship a small runtime: state() + full-page re-render on change (simple and correct), then later optimize with patching/diffing. 

// Nova
page home() {
  let count = state(0)
  func inc() { count += 1 }

  html {
    <div>
      <div>Count: {count}</div>
      <button onclick={inc}>+</button>
    </div>
  }
}

Standard library differences

  • Explicit conversions: toInt, toNum, toStr.
  • Logging: print() compiles to console.log for browser targets.
  • Web runtime: mount(node, selector), run PageName, state(value).

JavaScript interoperability

  • Nova can import JS modules directly.
  • JS interop boundaries can require explicit typing (extern) to keep safety guarantees.
  • All Web APIs remain available (fetch, canvas, WebAudio, etc.).
Note: Imported JS can still behave like JS. Nova’s “no coercion” rules apply to Nova code at compile-time.
